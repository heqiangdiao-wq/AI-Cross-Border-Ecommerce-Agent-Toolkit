# 模板 · 上架素材包

每份素材包对应一个商品、目标平台、市场和素材版本。按[串联工作流](../workflow.md)整理成果，发布前按[交付自检清单](../docs/04_Result_Checklist.md)人工复核。

## 目录结构

```text
listing-pack/
├── README.md                     # 上架信息、素材版本和审核记录
├── publish/                      # 复核通过的买家可见内容
│   ├── listing.md                # 最终标题、详情页及适用的平台字段
│   ├── images/                   # 主图、详情图，按上架顺序命名
│   │   ├── 01-main.jpg
│   │   └── 02-selling-point.jpg
│   └── videos/                   # 上架范围包含视频时，放审核通过的成片
│       └── 15s.mp4
└── working/                      # 内部交接、制作和审核材料
    ├── 01-market-analysis.md
    ├── 02-product-strategy.md
    ├── 03-listing-pack.md         # 含备选标题、关键词和合规扫描
    ├── product-brief.md          # 03 → 04/05 的共享字段
    ├── 04-image-plan.md          # 图位规划、制作要求和出图 Prompt
    ├── 05-video-plan.md          # 脚本、分镜、配音和字幕
    └── qa.md                     # 适用的检查项、结果和待修问题
```

图位和视频文件为示例。按目标平台要求选择成品格式，用两位数字给图片排序，并在 `README.md` 中记录实际要上传的文件和顺序。视频按计划上架时记录版本及用途。把确认后的可发布文本填入 `publish/listing.md`，将备选方案、制作 Prompt、内部备注和成本留在 `working/`。发布时只使用 `publish/` 中列入本次上架清单的内容。

## 素材包 README 模板

```markdown
# <商品名> · <目标平台> · <目标市场>

- 素材版本 <v1>
- 审核状态 <待审核 / 待补齐 / 可发布 / 已上架>
- 使用的 Prompt 版本或仓库提交 <版本或 commit>
- 复核人及日期 <姓名或角色，YYYY-MM-DD>
- 上架版本及日期 <发布后填写>

## 上架清单

| 平台字段或用途 | 文件 | 备注 |
|---|---|---|
| 标题与详情页 | `publish/listing.md` | |
| 主图与详情图 | <逐个列出 publish/images/ 内的路径> | 记录上传顺序 |
| 视频 | <列出 publish/videos/ 内的路径，或填本次不适用> | 记录使用场景 |

## 审核与变更记录

- 自检结果见 `working/qa.md`
- 待补齐的内容 <列出文件、原因及处理人，全部通过后填无>
- 本版变更 <首次上架或本次回改的病因、素材与复测指标>
```

运营侧的广告诊断和评论洞察可归入对应上架版本的内部记录。回改后保留旧版本，记录新版本对应的病因和变更文件，便于将复测数据与基线对应起来。
